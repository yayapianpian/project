# 06 後續開發順序與驗收標準

每一階段結束時都要：功能可在瀏覽器實際操作 → 自動測試通過 → 推上 GitHub 並部署預覽 → 才進入下一階段。

## 第 2 階段：專案骨架、資料層、能力診斷、首頁儀表板

**為什麼能力診斷放在這一階段**：儀表板與個人化計畫都依賴診斷結果，先做診斷才能讓首頁顯示真實數據，而不是假資料。

- Vite + React + TS + Tailwind 骨架；左側導覽、12 個頁面路由、深淺色切換、RWD。
- Dexie 資料庫（03 文件的 schema）、備份匯出／匯入、`storage.persist()`。
- 核心邏輯：熟練度計算、能力分數、分級（04 文件），附單元測試。
- 能力診斷：題庫第一版（30–36 題，選擇／填空／簡易 SQL 判讀）、自適應出題、結果頁。
- 180 天計畫產生器（以課程大綱模板 + 診斷結果產生 `planDays`）。
- 首頁儀表板：今日任務、進度、雷達圖、成績統計、弱項、下一個任務。

**驗收**：新使用者完成診斷 → 看到個人化計畫與儀表板；重新整理後資料仍在；匯出再匯入資料一致；手機寬度版面正常。

## 第 3 階段：六個月課程與教學內容

- 課程大綱 `curriculum.json`：6 階段 × 約 26 週 × 每日任務。
- 概念清單（約 120 個概念標籤）。
- 模擬資料集產生器（零售、電商、SQL 企業資料庫、金融、行銷、製造、物流）。
- 課程閱讀器與單元結構（02 文件 B3 的 8 個區塊）。
- 內容撰寫優先順序：**第 2 個月 SQL 與第 1 個月資料分析基礎先完整**，再依序補齊其他月份（使用者最需要的先到）。每單元通過 `validate-content` 檢查。

**驗收**：第 1、2 個月所有單元可閱讀、範例可送到練習室；其他月份至少大綱與每週第一單元完成。

## 第 4 階段：互動式測驗與練習

- PGlite SQL 練習室（含結果比對批改器與「錯在哪」診斷規則）。
- Pyodide Python 練習室（Worker、逾時、檢查程式）。
- 試算表公式題（HyperFormula）、DAX 數值驗證題。
- 三段式引導（A1）、測驗中心全部題型與限時模擬考、結果頁解析。
- 錯題本與 Leitner 複習。
- 弱點偵測與補強排程（A3），包含章節閘門。

**驗收**：每種題型至少 10 題可作答並正確批改；故意連錯 3 次 JOIN 題 → 明天任務出現 JOIN 補強、下一章被鎖；錯題在排定日期出現。

## 第 5 階段：產業模擬專案

- 主管出題模式全流程（A2）：任務簡報、追問主管、分步檢查點、結構化報告、評分表、合格門檻。
- 6 產業各至少 1 個初階任務（電商「營收下降 15%」優先，並把使用者既有的 RFM 經驗升級為完整企業分析案例），之後補齊進階任務。
- Power BI 實戰中心（資料下載、DAX 題、截圖交付與評分表）。

**驗收**：可完整走完電商任務並得到四項評分；只交圖表、無洞察的報告被判定不合格；其他 5 產業任務可開始並提交。

## 第 6 階段：進度、錯題、作品集、AI 導師、面試中心

- 個人能力分析頁（熱力圖、成長曲線、距離求職標準）。
- 作品集頁與 HTML / Markdown 匯出。
- 求職面試中心（履歷工作坊、題庫、筆試模擬、主管面試模擬）。
- AI 導師（BYOK、引導模式、程式批改、報告評估、花費計量與預算上限）。

**驗收**：結案專案自動出現在作品集並可匯出；未設定 Key 時 AI 頁誠實顯示未啟用，設定後可實際對話並顯示花費。

## 第 7 階段：全功能測試與修復

- Playwright 端對端腳本走完「九、最終驗收標準」的 9 項（下表），並點擊每一個按鈕確認有實際作用。
- 內容檢查：每題標準答案都能在引擎中跑出正確結果。
- 效能：首頁首次載入 < 2 秒（不含練習引擎）；Lighthouse 無障礙 ≥ 90。
- 資料安全：模擬升級 schema、匯入舊版備份。

## 待使用者確認的方向（會影響課程內容，但不阻擋第 2 階段開工）

1. **目標職缺類型**：預設以「電商／零售數據分析師」為主軸（與你的 RFM 經驗最接近），金融、行銷、製造、物流為延伸。若想主攻其他產業，第 3 階段會調整範例資料與專案比重。
2. **每日學習時間**：預設平日 2 小時、週末 3 小時；計畫產生器會依此分配。
3. **SQL 方言**：預設 PostgreSQL 語法，並在課程中標註 MySQL / SQL Server 的差異（台灣職缺常見 SQL Server、MySQL）。
