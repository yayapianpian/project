# 04 評分與能力評估制度

## 1. 基本原則

1. **只有「表現證據」會加分**：測驗、練習題提交、專案評分、面試模擬。觀看課程、標記已讀、完成任務打勾 → **0 分**。
2. **證據不足就不給分級**：避免做 2 題全對就被判定「良好實務能力」。
3. **越近期、越難、越少提示，權重越高**。
4. **專案用主管角度評分**：只完成圖表不算合格。
5. 所有分數都可以由原始作答紀錄**重算**，演算法改版時一致更新。

## 2. 100 分制能力組成

| 能力 | 滿分 | 證據來源 |
|---|---|---|
| 資料處理 | 20 | 試算表公式題、資料清理題（SQL/Python 中標記 `data.*` 概念）、專案「資料清理」項 |
| SQL | 20 | SQL 練習、SQL 測驗、模擬考、專案 SQL 檢查點 |
| Python | 15 | Python 練習、測驗、專案 Python 檢查點 |
| Power BI | 15 | DAX 數值驗證題、Power BI 觀念題、儀表板評分表 |
| 商業分析能力 | 20 | 商業情境題、資料分析題、專案「分析邏輯／商業洞察／建議可行性」 |
| 專案表達能力 | 10 | 專案報告結構與清晰度、面試「說明你的專案」評分 |

**總分 = Σ 各能力熟練度（0–1）× 該能力滿分**

## 3. 概念熟練度計算

每個概念（例如 `sql.window.rank`）的熟練度 `m ∈ [0,1]`：

```
每筆作答的證據值  e = scoreRatio × hintFactor
  hintFactor：無提示 1.0、第一段 0.8、第二段 0.5、看答案 0
每筆作答的權重    w = difficultyWeight × contextWeight × recencyDecay
  difficultyWeight：難度 1→0.6、2→0.8、3→1.0、4→1.2、5→1.4
  contextWeight：  lesson/practice 0.7、quiz 1.0、exam/project 1.3、diagnostic 1.0
  recencyDecay：   0.5 ^ (距今天數 / 30)    ← 30 天半衰期，舊表現逐漸淡出
m = (Σ w·e + 1·0.3) / (Σ w + 1)            ← 加一筆 0.3 的先驗，避免少量證據就極端
```

- `evidenceCount < 4` → 狀態 `unknown`，畫面顯示「證據不足」，該概念不參與分級展示（但仍計入計算）。
- 先驗值 0.3：沒有證據時偏保守；診斷測驗會取代先驗作為起點。
- 練習時「執行」不算作答，只有「提交批改」才寫入 attempts。

## 4. 能力分數

```
能力熟練度 = Σ(概念熟練度 × 概念重要性) / Σ 概念重要性
```

概念重要性由課程設計者設定（例如 SQL 中 `JOIN`、`GROUP BY`、`Window Functions` 重要性 3；`字串處理` 重要性 1），反映企業筆試與實務使用頻率。

**專案分數併入方式**：已結案專案的評分表各項，對應到能力（例如「技術正確性」→ SQL/Python，「商業洞察」→ 商業分析，「報告清晰度」→ 專案表達），以 contextWeight 1.3 當作一筆證據寫入對應的概念群。

## 5. 分級

| 分數（每項能力換算成 0–100，或總分） | 等級 |
|---|---|
| 0–39 | 初學者 |
| 40–59 | 基礎建立中 |
| 60–74 | 具備基礎實作能力 |
| 75–89 | 具備獨立分析能力 |
| 90–100 | 具備良好實務能力 |

**額外限制（防止灌分）**：
- 一項能力要顯示 ≥ 75「具備獨立分析能力」，須至少有 1 次**限時測驗或專案**證據。
- 一項能力要顯示 ≥ 90，須至少通過 1 個**進階產業專案**中相關的評分項目。
- 未達條件時，分數照算，但等級上限停在前一級，並提示「再完成 X 可解鎖」。

## 6. 測驗分數與能力評級

- 單次測驗分數 = Σ(題目分數 × 題目配分) / 總配分 × 100。
- 多選題部分給分：`max(0, (答對選項 − 答錯選項) / 正確選項數)`。
- 程式題：結果完全正確 100%；結果正確但未使用指定語法 70%；部分欄位正確依檢查點比例給分。
- 測驗結果頁的「能力評級」= 此次測驗分數對應第 5 節的等級，同時顯示「此次測驗後你的 SQL 能力分數從 52 → 58」。

## 7. 專案（主管評分）評分表範例：電商營收下降分析

| 評分項目 | 權重 | 4 分（優秀） | 2 分（及格邊緣） | 0 分 |
|---|---|---|---|---|
| 技術正確性 | 25 | SQL/Python 結果正確；清理了重複訂單與退款；數字可重現 | 主要數字正確但有 1–2 處清理遺漏 | 數字錯誤或無法重現 |
| 分析邏輯 | 25 | 先釐清口徑；將營收拆解為「流量 × 轉換率 × 客單價」並逐層下鑽 | 有比較但未拆解，靠圖表觀察 | 只描述「營收下降了」 |
| 商業洞察 | 30 | 找出主因並**量化貢獻**（例如「App 新客轉換率下降貢獻 −10.5%」），區分主因與次因 | 找到主因但未量化 | 只列現象、無因果判斷 |
| 建議可行性 | 20 | 3 項建議皆對應主因、有負責單位、可衡量指標與預估效益 | 建議合理但籠統 | 建議與分析無關 |

- 合格：四項各自 ≥ 50%（2 分）且加權總分 ≥ 70。
- 自動批改部分：技術正確性（檢查點）、商業洞察中的結構化答案（主因選擇與量化數值，容差 ±2%）。
- 文字部分：使用者先**自評**（看參考答案前），再顯示參考答案讓使用者對照修正；有 AI 時另給 AI 評分與評語。最終分數採 `自動分 + min(自評, AI 評分)`，避免自評灌分。沒有 AI 時，文字部分採自評但上限為該項的 75%，並標示「自評」。

## 8. 求職準備度

另外顯示「求職準備度」檢核（不是分數加總）：

- [ ] 總分 ≥ 70，且 SQL、商業分析 ≥ 75
- [ ] 至少 3 個已結案作品，涵蓋至少 2 個產業
- [ ] 完成 2 次限時企業筆試模擬，分數 ≥ 70
- [ ] 完成 3 次主管面試模擬
- [ ] 履歷檢核表全數通過
